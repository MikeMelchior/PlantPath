The Prisma client is generated to `./generated/prisma` (not `node_modules/.prisma`). It is regenerated by `postinstall` and by any `db:*` command that runs migrations. Import types from `generated/prisma` (see `src/server/api/routers/plant.ts`) and the client via `~/server/db`.

## Architecture

**Read `ARCHITECTURE.md` before making non-trivial schema or tRPC changes.** It documents the *why* behind decisions that are easy to undo accidentally: Clerk-for-identity-but-not-tenancy, the `PlantParent` join table, soft-delete-on-plants-only, and the cascade asymmetry on `PlantParent` (`child: Cascade`, `parent: Restrict`) that *forces* plants to soft-delete.

For project framing (portfolio goals, phase roadmap, current phase) and the domain glossary (F0/F1, selfing, stabilization, etc.), see `foundational-spec.md`. Use the glossary's terms verbatim.

### tRPC procedure layering

All authorization is done via composed procedures in `src/server/api/trpc.ts`. Use the most specific procedure that fits — do not reimplement these checks inside resolvers.

- `publicProcedure` — no auth.
- `protectedProcedure` — requires Clerk session. **Self-heals a missing `User` row by upserting from Clerk** (the webhook is best-effort; this is the guarantee). Downstream resolvers can rely on `ctx.userId` being a valid FK.
- `workspaceProcedure` — requires `workspaceId` in input. Looks up the `WorkspaceMember` row and attaches `ctx.membership` (with role). Throws `FORBIDDEN` if not a member.
- `editorProcedure` — composes `workspaceProcedure` and rejects `VIEWER`. Use for any mutation that modifies workspace data.

When adding a new router, register it in `src/server/api/root.ts`. The router map key becomes the client-side namespace (`api.plant.list`, etc.).

### Multi-tenancy enforcement

Every domain row carries `workspaceId`. There is **no row-level security in Postgres** — tenancy is enforced entirely at the tRPC layer through the procedures above. When writing queries:

- Always include `workspaceId` in the `where` clause for defense-in-depth, even after `workspaceProcedure` has authorized the request.
- For soft-deletable models (currently only `Plant`), default queries must filter `deletedAt: null`.
- `PlantParent` has no `workspaceId` column — it inherits scope through the plants it connects. Cross-workspace edges must be prevented at write time by the resolver (join back to `Plant` to verify).

### Clerk user mirror

Local `User` rows are populated two ways:
1. **Webhook** (`src/app/api/webhooks/clerk/route.ts`) — Svix-verified, idempotent (`upsert` on create/update, `deleteMany` on delete). Returns 4xx for permanent failures (don't retry) and 5xx for transient ones (do retry).
2. **Self-heal** in `protectedProcedure` — if a Clerk-authenticated request arrives with no local `User` row (webhook missed, local dev without a tunnel), the procedure upserts the row from Clerk's API before proceeding.

`User.id` is the raw Clerk user ID string (`user_2abc...`), not a cuid. This is intentional — see ARCHITECTURE.md.

### Routes & layouts

- `src/app/layout.tsx` — root layout, wraps everything in `ClerkProvider` + `TRPCReactProvider`.
- `src/app/(authed)/layout.tsx` — route group that gates everything beneath on `auth()`, redirecting to `/sign-in` if no session. Renders the shared header. Anything that requires login goes under `(authed)/`.
- `src/app/(authed)/w/[slug]/` — workspace-scoped pages. Slug is the URL handle (stable on rename); resolve to `workspaceId` via `workspace.getBySlug`.
- `src/app/api/trpc/[trpc]/` — tRPC HTTP handler.
- `src/app/api/webhooks/clerk/` — Clerk webhook receiver.

`middleware.ts` runs `clerkMiddleware()` for all non-static routes. It only attaches session context; route protection is done in the `(authed)` layout, not the middleware.

### tRPC clients

- **Server components** import from `~/trpc/server` (`api.foo.bar(...)` — direct caller, no HTTP).
- **Client components** import from `~/trpc/react` (`api.foo.bar.useQuery(...)`).
- `RouterInputs` / `RouterOutputs` in `~/trpc/react` give you typed shapes for inputs and outputs without writing them out.

A `timingMiddleware` injects a **random 100–500ms artificial delay in dev** to surface request-waterfall bugs that would only show up in production. If something feels slow locally, that's why.

## Conventions

- Path alias `~/*` → `src/*` (set in `tsconfig.json`). Use it; don't write relative imports across `src/` boundaries.
- TypeScript is strict with `noUncheckedIndexedAccess` — array/index access returns `T | undefined`.
- ESLint runs the type-checked config (`recommendedTypeChecked` + `stylisticTypeChecked`). Type-aware lint rules will fail `npm run check` if you ignore them.
- shadcn/ui is installed with the `radix-nova` style; components live in `src/components/ui/`. Use `npx shadcn@latest add <component>` to add new ones — don't hand-write them.
- Env vars must be added to `src/env.js` (`@t3-oss/env-nextjs`). Importing `process.env.FOO` directly bypasses validation and won't work in the edge runtime.
